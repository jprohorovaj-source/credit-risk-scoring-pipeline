## О проекте

**Credit Risk Scoring Pipeline** — end-to-end проект по построению модели кредитного риска для прогнозирования вероятности дефолта клиента.

Основная задача — разработать устойчивый ML-пайплайн, который способен работать с большим объёмом исходных данных, выполнить подготовку и агрегацию кредитной истории, обучить модель бинарной классификации и оценить её качество с использованием метрик, применяемых в задачах credit risk.

Проект ориентирован не только на получение значения ROC-AUC, но и на построение воспроизводимого процесса:

**сырые данные → подготовка → агрегация кредитной истории → формирование признаков → обучение модели → оценка качества → анализ результата.**

---

## Зачем нужен этот проект

В кредитном скоринге необходимо заранее оценивать вероятность того, что клиент допустит дефолт.

Ошибка модели может иметь разную стоимость:

* если надёжному клиенту отказать в кредите — бизнес теряет потенциальный доход;
* если кредит выдать высокорисковому клиенту — возрастает вероятность финансовых потерь;
* поэтому одной accuracy недостаточно для оценки качества модели.

В проекте основное внимание уделяется **ROC-AUC** как метрике способности модели разделять клиентов с разным уровнем риска.

---

## Данные

В проекте использован большой набор обезличенных кредитных данных, представленных в нескольких Parquet-файлах.

Характеристики исходного набора:

* около **4,5 GB** данных;
* **12 Parquet-файлов**;
* около **3 млн кредитных записей**;
* исходные признаки представлены в обезличенном виде;
* целевая переменная отражает факт дефолта;
* доля положительного класса составляет около **3,55%**.

Такое распределение классов делает задачу существенно несбалансированной.

Дополнительная особенность данных — наличие нескольких записей кредитной истории для одного клиента. Поэтому перед обучением модели необходимо выполнить корректную агрегацию истории и сформировать единый набор признаков на уровне клиента.

---

## Основная задача

Целевая задача проекта — бинарная классификация:

```text
Клиент
   ↓
Кредитная история
   ↓
Агрегация признаков
   ↓
ML-модель
   ↓
P(default)
   ↓
Оценка кредитного риска
```

Модель должна научиться различать клиентов с высокой и низкой вероятностью дефолта.

---

## Основные этапы проекта

### 1. Загрузка и исследование данных

Проведён анализ структуры исходных Parquet-файлов, количества записей, признаков и распределения целевой переменной.

Из-за большого размера исходных данных используется обработка отдельных частей датасета вместо попытки загрузить весь массив непосредственно в оперативную память.

---

### 2. Работа с большими данными

Одной из инженерных задач проекта стала обработка набора размером около 4,5 GB в среде с ограниченным объёмом RAM.

Используется **chunk-based processing**, позволяющий:

* читать данные частями;
* выполнять агрегации без загрузки всего набора в память;
* контролировать потребление RAM;
* сохранять воспроизводимость обработки;
* подготовить данные для последующего ML-этапа.

Это позволяет отделить задачу хранения и подготовки больших данных от непосредственно обучения модели.

---

### 3. Формирование клиентского датасета

Исходные записи кредитной истории агрегируются до уровня клиента.

Для каждого клиента формируется единый набор признаков, характеризующий его предыдущую кредитную активность.

В результате получается аналитический датасет, пригодный для обучения бинарного классификатора.

---

### 4. Анализ дисбаланса классов

Целевая переменная является сильно несбалансированной:

* класс `0` — большинство клиентов;
* класс `1` — дефолтные клиенты;
* доля положительного класса — около **3,55%**.

Поэтому при обучении модели необходимо учитывать стоимость ошибок и дисбаланс классов.

В качестве одного из подходов используется `scale_pos_weight`.

---

### 5. Обучение модели

В качестве основной модели используется **LightGBM** — градиентный бустинг по деревьям решений, хорошо подходящий для табличных данных и задач кредитного риска.

Базовая конфигурация модели включает:

```text
n_estimators = 500
learning_rate = 0.05
num_leaves = 64
subsample = 0.8
colsample_bytree = 0.8
scale_pos_weight ≈ 27
```

Параметры подобраны с учётом структуры задачи и сильного дисбаланса целевого класса.

---

## Оценка качества

Для оценки модели используется прежде всего **ROC-AUC**.

ROC-AUC позволяет оценить, насколько хорошо модель ранжирует клиентов по уровню риска независимо от выбранного порога классификации.

Дополнительно результаты рассматриваются с учётом природы credit-risk задачи и дисбаланса классов.

---

## Результат

На базовой конфигурации LightGBM получено:

**ROC-AUC ≈ 0.714**

Этот результат показывает, что модель способна выявлять зависимость между обезличенной кредитной историей и вероятностью дефолта и существенно лучше случайного классификатора.

При этом значение ROC-AUC рассматривается не как конечная цель, а как baseline для дальнейшего улучшения модели.

## Ограничения проекта

Это исследовательский и учебно-практический ML-проект, а не готовая банковская система принятия кредитных решений.

Данные обезличены, а признаки не имеют интерпретируемых бизнес-названий.

Поэтому полученный результат нельзя напрямую использовать для реального кредитного решения без дополнительной работы с:

* интерпретируемостью признаков;
* калибровкой вероятностей;
* stability / drift monitoring;
* fairness-анализом;
* reject inference;
* model validation;
* regulatory requirements;
* экономической оценкой ошибок первого и второго рода.
